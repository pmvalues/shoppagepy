01

Module Overview

Shoppage Chat is not a separate app. It is a service layer and embedded UI module that turns every product inquiry into a structured commerce event. It lives inside the Shoppage buyer app and inside the Pemofy merchant dashboard.

For Buyers (Shoppage App)
Search a product, tap "Chat with Seller," and enter a structured conversation where every message has commerce meaning. Quotes are auto-generated from live inventory. Approvals create real orders. Tracking updates arrive in-thread.
For Merchants (Pemofy Dashboard)
All buyer conversations appear in a unified team inbox inside Pemofy. AI suggests replies based on inventory, pricing rules, and conversation history. Quotes, orders, and fulfillment status sync automatically. No manual re-keying.

Core Principles

PrincipleWhat It Means
Every message is structuredNot free text. Every message has a type, intent, and commerce payload that the system can act on.
Inventory is the source of truthNo quote can be generated without validating stock against Pemofy's inventory_levels table.
Approval is bindingWhen a buyer taps "Approve Quote," an order is created, stock is reserved, and a payment link is generated. No ambiguity.
Conversations are persistentA buyer's full conversation history, all quotes, all orders, all tracking, lives in one thread per merchant.
WhatsApp is fallback onlyShoppage Chat is primary. WhatsApp handles notifications and conversations with non-onboarded merchants.

03

Data Model

The canonical data lives in PostgreSQL. Redis handles ephemeral state (presence, typing, unread counts). Typesense powers merchant search within the team inbox.

Core Entities

conversations

  • id UUID PK
  • buyer_id UUID → buyers
  • merchant_id UUID → merchants
  • product_id UUID? (optional context)
  • status enum: active, closed, archived
  • quote_id UUID? (current open quote)
  • order_id UUID? (if converted)
  • last_message_at timestamp
  • unread_buyer int
  • unread_merchant int
  • channel enum: shoppage, whatsapp, mixed
  • created_at, updated_at

messages

  • id UUID PK
  • conversation_id UUID FK
  • sender_type enum: buyer, merchant, system, ai
  • sender_id UUID
  • message_type enum (see below)
  • content JSONB (structured payload)
  • text text (rendered text)
  • status enum: sending, sent, delivered, read, failed
  • reply_to_id UUID? (threading)
  • metadata JSONB
  • created_at

quotes

  • id UUID PK
  • conversation_id UUID FK
  • quote_number string (e.g. QUO-2026-001234)
  • status enum: draft, sent, viewed, approved, expired, cancelled
  • subtotal decimal
  • delivery_estimate decimal
  • vat decimal
  • total decimal
  • valid_until timestamp
  • stock_reserved_until timestamp
  • buyer_approval_at timestamp?
  • order_id UUID? (on approval)
  • pdf_url string
  • created_at, updated_at

quote_lines

  • id UUID PK
  • quote_id UUID FK
  • product_id UUID
  • variant_id UUID?
  • product_name string
  • quantity int
  • unit_price decimal
  • line_total decimal
  • stock_confirmed boolean
  • stock_location_id UUID?
  • metadata JSONB

buyer_chat_profiles

  • buyer_id UUID PK
  • display_name string
  • phone string (hashed)
  • email string?
  • default_postal_code string?
  • preferences JSONB
  • last_active_at timestamp
  • whatsapp_opt_in boolean
  • push_enabled boolean

merchant_chat_settings

  • merchant_id UUID PK
  • auto_quote_enabled boolean
  • auto_quote_rules JSONB
  • ai_suggestions_enabled boolean
  • response_time_sla int (minutes)
  • team_size int
  • away_message text?
  • business_hours JSONB
  • max_open_quotes int

Message Type Enum

TypeDescriptionContent Payload
textPlain text message{ text: string }
inquiryStructured product inquiry{ product_query, quantity, postal_code, urgency }
quoteStructured quote card{ quote_id, lines, totals, expiry }
quote_actionApprove / modify / cancel quote{ action, quote_id, reason? }
order_createdSystem message: order confirmed{ order_id, total, payment_link }
payment_requestPayment link or EFT details{ amount, method, link, expiry }

Design Note: All monetary values stored as DECIMAL(12,2) in ZAR. All timestamps UTC. content JSONB is schema-versioned (v1) to allow evolution without migrations.

8.3 Escalation Detection

The agent monitors every conversation for signals that require human intervention:

  • Sentiment drop: Negative sentiment score below -0.3 on any message
  • Price dispute: Buyer mentions competitor price or asks for >15% discount
  • Complex request: Multiple products, custom specifications, or installation requirements
  • SLA breach: Merchant has not replied within configured SLA (default 30 min)
  • Repeat inquiry: Same buyer asking same question 3+ times without resolution
  • High-value quote: Quote total exceeds R50,000

Escalation triggers: push notification to assigned merchant, highlight in inbox (red border), add to "Needs Attention" filter.

11

Security & Compliance

11.1 Authentication

  • Buyers: JWT via Shoppage auth (Google/Apple/phone OTP). Short-lived access tokens (15 min), refresh tokens (7 days).
  • Merchants: Pemofy session auth. Same auth system as dashboard. No separate chat login.
  • WebSocket: Token passed in connection query param; validated on connect. Reject unauthenticated connections.

11.2 Authorization

// Conversation access rules
Buyer can access conversation IF conversation.buyer_id == buyer.id
Merchant can access conversation IF conversation.merchant_id == merchant.id
Merchant team member can access IF assigned OR has "chat:read" role
AI agent can access ALL for processing but logs are anonymized

Buyer can send text, inquiry, quote_action in their conversations only

11.4 Fraud Prevention

  • Quote abuse: Rate limit 5 quotes/hour per buyer per merchant; CAPTCHA after 3 rapid inquiries
  • Fake merchant accounts: CIPC + bank verification (inherited from Pemofy) required before chat enabled
  • Payment interception: Payment links generated server-side with signed tokens; URL tampering detected
  • Conversation hijacking: WebSocket connections bound to authenticated user; cannot spoof sender_id
